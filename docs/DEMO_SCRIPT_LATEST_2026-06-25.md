# 智能桌面 AI 终端｜最新版现场演示脚本

更新时间：2026-06-25（北京时间）

适用状态：网页端“双重自检”逻辑仍在修改和联调。本版演示不把网页主动自检作为验收依据，正式开场以命令行只读检查 `verdict=PASS` 为准。

## 一、上台前启动

硬件上电后预留 1—3 分钟，让 ESP32S3 完成 Wi-Fi、WebSocket 和 STM32 UART 保活。

### 推荐：关键词语音激活模式

```powershell
.\tools\start_defense_demo.cmd -VoiceMode wakeword
```

启动器会：

1. 检查 ESP32S3 是否已直连阿里云 ECS；
2. 必要时启动本机 relay 兜底；
3. 等待只读实时检查通过；
4. 打开公网 Web 控制台；
5. 经本人确认后启动笔记本麦克风关键词监听。

默认关键词：

```text
灵宝灵宝
你好灵宝
```

关键词模式会持续捕获笔记本麦克风语句；只有 ASR 识别到关键词才会播报“我在”并进入后续对话。它与 KEY2 PTT 是两个独立模式，不能在同一个窗口中混用。KEY2 PTT 直接读取本机 COM7 的 STM32 按键事件，避免公网轮询延迟截断录音。

### 只展示网页和硬件

```powershell
.\tools\start_defense_demo.cmd -SkipVoice
```

### 单独启动关键词监听器

```powershell
python -u .\tools\laptop_realtime_listener.py `
  --base-url https://8-163-38-158.sslip.io `
  --device-id desktop-agent-001 `
  --input-device 1 `
  --input-mode vad `
  --no-auto-start-backend
```

如麦克风编号变化，先运行：

```powershell
.\tools\start_defense_demo.cmd -ListAudioDevices
```

## 二、正式演示稿（约 5 分钟）

### 1. 开场与真实状态证明（约 30 秒）

操作：

```powershell
python .\tools\realtime_readiness_check.py
```

确认输出为：

```text
"verdict": "PASS"
```

讲解：

> 大家好，我展示的是一套基于 STM32F103、ESP32S3、RFID、传感器和语音模块构成的智能桌面 AI 终端。开始演示前，我先运行只读实时检查，确认云端模型、设备在线状态、WebSocket、STM32 UART、传感器新鲜度和 ACK 队列都处于可演示状态。这里显示 PASS，说明接下来看到的是当前真实设备数据，不是历史截图或预设假数据。

边界说明：

> 网页端正在完善“双重自检”的交互逻辑，所以今天正式验收以这份命令行只读检查为准。网页按钮可以展示界面，但不把尚在联调的结果讲成已完成验收。

### 2. 四层架构（约 30 秒）

操作：打开 Web 控制台首页。

讲解：

> 系统分为四层：感知层由 STM32、RFID、温湿度、距离等传感器和执行器组成；网络层由 ESP32S3、Wi-Fi、WebSocket 和 UART 组成；平台层部署在阿里云 ECS，负责 FastAPI、Qwen、语音识别、状态管理和动作调度；应用层包括 Web 控制台和微信小程序。API Key 只保存在云端，单片机和前端都拿不到密钥。

### 3. 实时传感器（约 30 秒）

操作：打开“传感器”页面，轻微改变距离或电位器。

讲解：

> 这里展示的是 STM32 实际采集并经 ESP32S3 上传的实时数据。现在我改变距离或旋转电位器，页面数值随新的遥测更新。系统没有传感器数据时会显示未上报，不会自动补演示数值。

### 4. RFID 身份与上下文（约 40 秒）

操作：刷已注册的真实 RFID 卡，观察 OLED、网页用户与模式变化。

讲解：

> RFID 在这里不是装饰，而是用户身份和上下文入口。真实 RC522 刷卡后，系统会识别用户和模式，并把这个身份上下文用于后续对话和控制。网页里的模拟 UID 仅用于调试，正式演示使用真实刷卡。

### 5. AI 文本与硬件闭环（约 60 秒）

操作：在 Web 控制台输入：

```text
打开风扇并播报当前温度
```

讲解：

> 这条自然语言先进入云端 Qwen，模型根据当前传感器和用户上下文生成回复与动作。动作带有唯一 action ID，经 ESP32S3 下发给 STM32。风扇实际执行后，STM32 返回相同 action ID 的 ACK。只有收到 ACK，我才把它称为执行成功。

随后输入：

```text
现在环境怎么样？请结合温湿度和距离简短回答。
```

讲解：

> 这次不是固定控制命令，而是模型读取当前真实传感器上下文后生成回答。网页保留完整回复，SYN6288 播报适合现场聆听的短句。

### 6. 关键词语音激活闭环（约 60 秒）

操作：

1. 确认关键词监听窗口正在运行；
2. 清楚说：“灵宝灵宝”；
3. 听到“我在”后说：“现在环境怎么样，请告诉我温度和距离”；
4. 等待页面显示 ASR 文本、AI 回复、设备播报与 ACK。

讲解：

> 现在演示的是关键词激活。系统先用笔记本麦克风监听短语“灵宝灵宝”，关键词命中后才录制完整指令并上传识别。识别文本继续进入同一条 Qwen、TTS、硬件动作和 ACK 链路。因此语音和文本不是两套演示程序，而是共用同一个云端智能闭环。

必须如实说明：

> 当前稳定验收的语音入口是笔记本麦克风；ESP32S3 板载麦克风不作为本次已完成成果宣称。

### 7. 诊断与收尾（约 40 秒）

操作：打开“闭环链路”或“后台日志”，展示最近动作与 ACK。

讲解：

> 最后展示系统诊断信息。这里可以看到 ESP32S3 在线状态、STM32 UART、最近 ASR 文本、最近动作、ACK 成功数和待执行队列。当前错误 ACK 为零、待执行动作归零，说明本轮从输入、AI 决策、设备执行到确认回传已经闭环。

收尾：

> 这个项目的重点不是播放预设语音，而是把真实身份、真实传感器、自然语言 AI、实体执行器和可追踪 ACK 连接成一套可验证的智能桌面终端。

## 四、现场故障降级顺序

1. 网页双重自检仍在联调：不点击或不引用结果，展示命令行 readiness `PASS`。
2. 关键词连续两次未命中：直接使用 Web 文本输入，保住 AI → STM32 → ACK 主闭环。
3. 麦克风设备错误：运行 `-ListAudioDevices` 后更换 `-InputDevice`。
4. RFID 未读：移开卡片后重新靠近；不要把网页模拟 UID 说成真实刷卡。
5. 云端模型不可用：明确说明进入本地规则降级，不称为 Qwen 实时回复。
6. ESP32S3 直连波动：允许启动器使用 8091 relay 兜底，不临场修改 VPN、DNS、路由、防火墙或安全组。

## 五、禁止表述

- 不说“网页双重自检已经完成验收”。
- 不说“ESP32S3 板载麦克风已经稳定实现关键词唤醒”。
- 不把“命令已发送”说成“设备执行成功”，必须展示 ACK。
- 不把网页模拟 RFID 说成真实 RC522 刷卡。
- 不展示 `backend/.env`、API Key、服务器密码或控制口令。
