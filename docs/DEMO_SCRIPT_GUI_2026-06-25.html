智能桌面 AI 终端

五分钟答辩演示讲稿｜真实感知 · 身份上下文 · 云端 AI · 实体执行 · ACK

上台前

  1. 给 STM32、ESP32S3、传感器和执行器上电，等待 1—3 分钟。
  2. 双击 启动答辩演示.exe，确认界面中的云端、设备、UART、传感器均显示正常。
  3. 点击橙色的“一键启动完整演示”。程序会自动打开网页并启动关键词监听。
  4. 安全设置中输入本次控制口令；口令不要写在 PPT、讲稿或截图中。

正式讲解

1. 开场：先证明是真实系统

大家好，我展示的是一套由 STM32F103、ESP32S3、RFID、真实传感器和语音模块构成的智能桌面 AI 终端。启动器已经完成只读实时检查，当前云端模型、设备在线状态、STM32 UART、传感器新鲜度和动作队列均可演示，因此接下来看到的不是历史截图或预设假数据。

2. 四层架构

系统分为四层：STM32 负责真实感知与确定性执行；ESP32S3 负责 Wi-Fi、RFID 和串口桥接；阿里云 ECS 负责 FastAPI、Qwen、ASR、用户上下文和动作调度；应用层提供 Web、小程序和笔记本语音入口。密钥只保存在云端。

3. 真实传感器

操作：改变超声波距离或旋转电位器，观察网页数值刷新。
这些数据由 STM32 实际采集，经 ESP32S3 上传。没有数据时系统显示未上报；超过 30 秒没有新的硬件证据，会自动判定设备离线，不会拿旧快照冒充实时状态。

4. RFID 身份上下文

操作：刷已注册的真实 RC522 卡，观察网页用户、模式和 OLED 改变。
RFID 在这里不是装饰性的开锁功能，而是用户上下文入口。真实 UID 会绑定用户、模式、对话记忆和权限；未知卡不会继承上一位用户。网页模拟 UID 只用于调试。

5. AI 到硬件的闭环

输入：打开风扇并播报当前温度。
自然语言先进入 Qwen，模型结合实时传感器和当前用户上下文生成回答与动作。每个动作都有唯一 action_id，经 ESP32S3 下发给 STM32；STM32 实际执行后返回同一个 ID 的 ACK。只有收到 ACK，我们才把动作称为执行成功。

6. 关键词语音

说：“你好小鑫” → 听到“我在” → “现在环境怎么样，请告诉我温度和距离。”
语音和文字不是两套演示程序。关键词命中后，笔记本麦克风录制指令，Paraformer 完成识别，然后进入同一条 Qwen、动作规划、STM32 执行与 ACK 链路。当前稳定验收入口是笔记本麦克风；ESP32S3 板载 WakeNet 仍属于隔离实验分支。

7. 诊断与收尾

最后可以在诊断页面看到最近动作、ACK 成功数和待执行队列。这个项目的重点不是播放预设语音，而是把真实身份、真实环境、自然语言 AI、实体执行器和可追踪 ACK 连接成一套可验证的智能终端。

现场推荐语句

  • 关键词：你好小鑫
  • 环境问答：现在环境怎么样，请告诉我温度和距离。
  • 动作控制：打开风扇并播报当前温度。
  • 自由问答：你能为桌面环境做什么？
  • 收尾动作：关闭风扇。

故障降级顺序

  1. 语音连续两次未命中：点击“停止语音监听”，立即使用 Web 文本输入。
  2. RFID 偶发未读：移开卡片后重新靠近，不把网页模拟 UID 说成真实刷卡。
  3. 云端模型不可用：明确说明进入规则兜底，不称为 Qwen 实时回复。
  4. 设备状态未通过：检查硬件供电和 Wi-Fi，不在答辩现场修改 VPN、DNS、路由、防火墙或安全组。

禁止表述：板载麦克风已经稳定验收；命令发出就等于执行成功；模拟 RFID 就是真实刷卡；缓存状态就是实时设备状态。
